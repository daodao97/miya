# Miya 通知

桌面设置的「通知」分别控制任务完成和等待确认提醒。正在查看的会话不弹通知；恢复历史不会重新提醒。手动停止任务不发完成提醒。通知点击后返回对应会话。

完成通知优先展示本轮最终回复的首个有效正文句，跳过标题、代码块和 Codex 过程说明，清理 Markdown，最多 160 字，不额外调用模型。没有可用摘要时展示最近的任务请求，其次会话标题，最后使用完成提示；不会引用上一轮回复。失败通知显示本轮错误原因。等待确认时展示具体问题、授权原因或待执行命令，Claude 工具输入不会直接作为 JSON 展示。桌面和手机推送共用文案，后台会将完成文案随会话状态同步给桌面，无需订阅完整消息。

手机 Let’s build 页右上角的「设置」可开启或关闭手机通知。首次启动请求系统通知权限，并通过已配对的加密连接向桌面注册：iOS 注册 APNs token，进入后台后断开会话连接，由桌面后台服务经 APNs 发送；Android 见下文「Android」，经配对连接直接接收。角标显示该手机的未读会话数：同一会话的完成和审批通知只占一个名额。打开会话后会自动标为已读，设置页也可「全部标为已读」；关闭手机通知会清零。每台手机分别保存已读状态，旧回执不会清除之后收到的新通知。

桌面侧边栏的绿色圆点表示有尚未阅读的完成结果。当前对话的完成回复已显示、列表滚动到末尾且窗口在前台时，会自动清除圆点，无需重新点击对话。停留在历史消息、其他页面或后台窗口时保留未读。手机在前台打开会话并收到完整的完成结果后，也会同步清除电脑上的圆点；这不依赖手机通知权限或 APNs 注册。旧结果的已读回执不会清除更新的完成结果。

注册信息保存在桌面应用数据目录的 `push-devices.json`，文件权限为 0600；超过 90 天不再使用的注册不再发送。发送失败会有限重试。未读状态保存在同目录的 `push-unread.json`，权限为 0600；后台服务重启会保留计数。纯角标更新不会显示横幅或播放声音。

桌面 GUI 定期报告使用状态，人在电脑前时由桌面提醒，离开电脑约五分钟后由手机提醒。GUI 退出后，状态租约最多 25 秒过期。桌面服务必须运行且可访问 Apple APNs；关机时无法发送。

## 手机通知规则

手机推送默认安静：同一类提醒你一再不看，之后就只更新角标，不再响铃和弹横幅。规则由后台服务持有，保存在应用数据目录的 `push-policy.json`（权限 0600），在桌面「设置 › 通用 › 手机通知规则」里查看和修改。没有连接后台服务时不显示这一组。

**类别。** 每条提醒带一个类别：普通对话的完成按项目分（`completion:<项目路径>`），自动化结果按自动化分（`automation:<ID>`），条件检查失败按自动化分（`probe:<ID>`），另有没有自动化接收的 Webhook（`webhook`）和每日简报（`briefing`）。

**紧急提醒不学习。** 审批与提问、等待复核、自动化停滞、失败（对话失败或自动化运行失败）、`needs_user` 的结果总会弹横幅，不受规则影响，也不计入学习。

**怎么学。** 服务端只看得到两种反应：在手机上打开了对应会话（`read`），或者用「全部标为已读」清掉了它（`read-all`）。

- 同一类别的横幅提醒连续 2 次没打开就被清掉，这一类以后只更新角标。中间打开过一次，计数重来。
- 已经静音的类别，连续 2 次打开它的会话，规则自动解除；中间又有一次没打开就清掉，计数重来。
- 在电脑上读过的会话（桌面的已读回执），算作打开，之后在手机上清掉也不算忽略。
- 同一条提醒在多台手机上只计一次。
- 设置页每条规则旁有「恢复提醒」，删除规则并清零计数。

**免打扰时段。** 默认关闭，开启后默认 22:00–08:00，可以跨午夜。时段内所有提醒（包括紧急提醒）只更新角标，不计入学习；未读和角标照常累计，醒来后打开手机就能看到。时间按后台服务所在电脑的本地时区。

**限制。** 学习只依据「打开」和「全部已读」两种反应，读不懂提醒之后你在对话里说的话；「以后这种直接告诉我」这类明确指令还不能直接变成规则。手机端暂时没有规则管理页面。桌面窗口自己弹出的通知（不经后台服务时）不受这些规则影响。

## Android

Android 不使用第三方推送服务。开启手机通知并配对电脑后，Miya 在通知栏常驻一条低优先级通知「正在接收电脑通知」（前台服务，`mygo.Power.KeepRunning`），退到后台时保持与电脑的 tailcat 加密连接；桌面直接经这条连接发送通知，内容不经第三方，也不需要配置发送端。文案、角标、未读、正在查看的会话不弹、人在电脑前不发，都与 iOS 相同；点击通知打开对应会话。

限制：Miya 被系统清理或被用户结束后收不到通知，重新打开后读取未读状态，不补发错过的提醒。部分国产 ROM 需要允许 Miya 自启动或忽略电池优化。电脑关机或休眠时同样无法发送。设计与验收见 [Android 通知](android-push-design.md)。

## 配置发送端

在本项目目录运行（密钥路径替换成自己的文件）：

```sh
go tool mygo push setup -team XNDA84PBM3 -environment sandbox /path/to/AuthKey_KEYID.p8
go tool mygo push status
```

默认使用 `com.daodao.miya` 和应用数据目录 `Miya`。如果服务设置了 `MIYA_DIR`，配置时追加 `-data-dir "$MIYA_DIR"`（放在密钥路径前）。密钥只保存在桌面端，由 MyGo 管理；不会传给手机或打包进应用。

开发签名使用 sandbox；TestFlight/App Store 使用 production，并确保手机构建的 aps-environment 与发送端环境一致。`mygo.json` 已开启 `ios.pushNotifications`。Apple Developer 中的 Miya App ID 必须开启 Push Notifications，重新生成包含该能力的 provisioning profile 后重建安装：

```sh
./scripts/build-ios.sh
```

手机系统设置必须允许 Miya 通知。若首次弹窗拒绝，可从系统设置开启后回到应用。手机设置页显示注册和发送端未配置的错误。尚未配置 APNs 时，桌面通知仍可使用；手机后台送达无法工作。

## 验证

1. 用手机配对桌面，确认允许通知，进入手机设置页确认通知开启。
2. 在另一个会话运行任务，当前会话被查看时应保持安静。
3. 将手机退到后台，退出桌面 GUI（保持后台服务运行），等待租约过期，然后让任务结束或触发审批。
4. 点击手机通知，确认打开对应会话；冷启动和已有连接都应测试。
5. 关闭手机通知后重新触发任务，确认不再收到推送。

单元测试覆盖完成状态转换、历史/停止抑制、注册参数验证和桌面/手机路由。真实 APNs 送达需要有效 Apple 凭据与真机签名，不能由单元测试代替。
