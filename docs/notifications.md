# Miya 通知

桌面设置的「通知」分别控制任务完成和等待确认提醒。正在查看的会话不弹通知；恢复历史不会重新提醒。手动停止任务不发完成提醒。通知点击后返回对应会话。

完成通知优先展示本轮最终回复的首个有效正文句，跳过标题、代码块和 Codex 过程说明，清理 Markdown，最多 160 字，不额外调用模型。没有可用摘要时展示最近的任务请求，其次会话标题，最后使用完成提示；不会引用上一轮回复。失败通知显示本轮错误原因。等待确认时展示具体问题、授权原因或待执行命令，Claude 工具输入不会直接作为 JSON 展示。桌面和手机推送共用文案，后台会将完成文案随会话状态同步给桌面，无需订阅完整消息。

手机 Let’s build 页右上角的「设置」可开启或关闭手机通知。首次启动请求系统通知权限，并通过已配对的加密连接向桌面注册 APNs token。手机进入后台会断开会话连接，桌面后台服务仍负责发送通知。角标显示该手机的未读会话数：同一会话的完成和审批通知只占一个名额。打开会话后会自动标为已读，设置页也可「全部标为已读」；关闭手机通知会清零。每台手机分别保存已读状态，旧回执不会清除之后收到的新通知。

注册信息保存在桌面应用数据目录的 `push-devices.json`，文件权限为 0600；超过 90 天不再使用的注册不再发送。发送失败会有限重试。未读状态保存在同目录的 `push-unread.json`，权限为 0600；后台服务重启会保留计数。纯角标更新不会显示横幅或播放声音。

桌面 GUI 定期报告使用状态，人在电脑前时由桌面提醒，离开电脑约五分钟后由手机提醒。GUI 退出后，状态租约最多 25 秒过期。桌面服务必须运行且可访问 Apple APNs；关机时无法发送。

## 配置发送端

在本项目目录运行（密钥路径替换成自己的文件）：

```sh
go tool mygo push setup -team XNDA84PBM3 -environment sandbox /path/to/AuthKey_KEYID.p8
go tool mygo push status
```

默认使用 `com.daodao.miya` 和应用数据目录 `Miya`。如果服务设置了 `MIYA_DIR`，配置时追加 `-data-dir "$MIYA_DIR"`（放在密钥路径前）。密钥只保存在桌面端，由 MyGo 管理；不会传给手机或打包进应用。

开发签名使用 sandbox；TestFlight/App Store 使用 production，并确保手机构建的 aps-environment 与发送端环境一致。`mygo.json` 已开启 `ios.pushNotifications`。Apple Developer 中的 Miya App ID 必须开启 Push Notifications，重新生成包含该能力的 provisioning profile 后重建安装：

```sh
./scripts/build-ios.sh
```

手机系统设置必须允许 Miya 通知。若首次弹窗拒绝，可从系统设置开启后回到应用。手机设置页显示注册和发送端未配置的错误。尚未配置 APNs 时，桌面通知仍可使用；手机后台送达无法工作。

## 验证

1. 用手机配对桌面，确认允许通知，进入手机设置页确认通知开启。
2. 在另一个会话运行任务，当前会话被查看时应保持安静。
3. 将手机退到后台，退出桌面 GUI（保持后台服务运行），等待租约过期，然后让任务结束或触发审批。
4. 点击手机通知，确认打开对应会话；冷启动和已有连接都应测试。
5. 关闭手机通知后重新触发任务，确认不再收到推送。

单元测试覆盖完成状态转换、历史/停止抑制、注册参数验证和桌面/手机路由。真实 APNs 送达需要有效 Apple 凭据与真机签名，不能由单元测试代替。
