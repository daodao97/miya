# 会话引用使用后端会话身份

会话引用由来源、后端和后端原始会话 ID 确定。标题用于展示，项目路径用于定位记录；本地 `Thread.ID` 只供 UI 和内部请求使用。

```text
miya://<source-id>/thread/<backend>/<session-id>
```

- `source-id` 是 Miya 数据实例的 32 位小写十六进制标识，保存在 `serviceDir()/reference-source`。重启、更新、重置手机配对均不改变它。这个文件损坏时停止生成引用，不自动换身份。
- `backend` 为 `codex` 或 `claude-code`。
- `session-id` 是原始 `ServerID`，区分大小写，按单个 URL 路径段编码；解析要求使用完整、规范的链接，不接受前缀、查询参数、片段或认证信息。
- 另一来源的引用不能在当前桌面解析；链接不包含连接凭证，也不赋予访问权限。

## 输入和剪贴板

输入 `@` 后按标题或会话 ID 搜索，候选项显示标题、后端和项目。选中后显示标题标签。没有后端会话 ID 的新对话暂时不可引用。

消息的结构化内容使用 `MessagePart`，引用段保存 `ThreadRef` 和 `titleSnapshot`。草稿、纯文本剪贴板和后端历史使用以下可往返的显式拼写：

```text
@[登录修复](miya://0123456789abcdef0123456789abcdef/thread/codex/session-id)
```

标题中的反斜杠和方括号转义，空白规范化为单个空格。标题的变化不改变目标。不同 ID 的同名会话始终是两个引用。

消息中的会话链接和引用标签可点击，在当前连接的桌面实例内按完整身份跳转，支持跨项目、跨 Agent 打开；跳转会收起任务弹层。其他桌面来源、已删除或不可用的目标显示不可用提示，不按标题或本地数字 ID 猜测目标。

普通会话链接是文本，不自动加载上下文。在输入框的上下文菜单中选择「粘贴为会话引用」进行转换；选中一个引用标签后可选择「复制会话链接」。普通复制、剪切、粘贴和撤销保留引用身份及标题快照。

代码块、行内代码及反斜杠转义的引用拼写保持字面文本。代码范围使用与消息渲染相同的 Markdown 解析器判定。

## 发送、编辑和分支

发送前按完整身份解析引用并检查历史是否加载。缺失、来源不匹配、自引用或历史未加载都会阻止发送，保留草稿并提示重试或移除引用。选择引用会预取历史，预取缓存按完整身份隔离。

发送时把所用上下文保存到版本为 2 的 JSON 上下文包。正文保留显式引用，不根据标题重建 ID。显示与编辑隐藏经过校验的上下文包，保留其外的正文和附件说明。代码示例和普通上下文标签不会截断正文。

引用只读取来源会话的上下文，不向来源会话追加消息或建立任务进度关联。只有明确调用 MCP `delegate` 委派任务时，才在调用方显示「已交付到对话」并跟踪目标进度；这与是否携带调用方上下文无关，任务中引用的其他会话也不会成为委派方。

排队消息各自保留提交时的上下文快照；合并发送时合并正文和快照，不重新读取源会话。把排队消息放回输入框编辑时，移除旧快照，下次发送重新取上下文。

编辑历史导致后端创建新会话时，既有引用继续指向原始会话。原会话的定位元数据保存在 `serviceDir()/reference-sessions.json`，重启后可从原后端记录加载；不会把旧 ID 别名到新分支。

## 工具接口和协议

MCP 的 `list_threads` 返回完整会话链接；`read_thread.id`、`thread_status.id` 和 `delegate.thread_id` 使用该链接字符串，不再接收数字编号。创建中的目标会话在后端返回 ID 前仍由服务内部跟踪。

桌面服务状态和手机状态都携带 `referenceSource`。服务协议版本为 2，手机协议版本为 5，需使用对应版本的窗口、后台与手机端。

旧 `@#数字` 只作为普通文本，不提供迁移或兼容解析。
