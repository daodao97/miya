# 自动化（Automations）

到了设定的时间，Miya 在指定项目里新开一个对话，用指定的 agent 发出一段固定的指令。设置了检查命令时，一轮结束后在项目目录执行它，没通过就把输出发回同一个对话继续下一轮，直到通过或轮数用完。运行结束后推送到手机。

界面原型在 [automations-ui.html](automations-ui.html)。

## 创建

两种方式都只需要一句话，例如「每个工作日早上 9 点看一下新 Issue，能修的修掉并保证 go test 通过，修不过就多试两次」。

- **Automations 页面**：写一句话，选项目和 agent。停止输入 1 秒后，所选 agent 做一次不带工具的调用，按 JSON schema 回答名称、cron、检查命令、轮数和发给 agent 的指令（`automation_parse.go`）。Claude Code 用 `-p --json-schema --output-format json --tools ''`，Codex 用 `exec --output-schema -o --sandbox read-only --ephemeral`。提示词里带上当前时间和项目顶层文件，用来推断检查命令。结果显示在「整理结果」里，每一项都能单独改。
- **对话里**：miya MCP 的 `create_automation` 由对话里的 agent 填好结构化字段。Miya 在这个对话里显示确认卡片，用户点「允许」才创建；10 分钟没处理按取消算。`update_automation` 改开关时直接生效，改其他内容同样要确认，卡片显示改前和改后。`list_automations` 只读，Claude Code 不用确认就能调用。

Miya 用确定性代码校验 agent 的结果：cron 由 `automation_cron.go` 解析，非法时报错；轮数限制在 1 到 5，没有检查命令时为 1；句子没写时间时暂定每天 9:00，并在界面上标黄；检查命令开头的 `cd <项目> &&` 会被去掉。

## 数据

一个自动化有名称、项目、agent、原话、指令、cron、检查命令、最多轮数和启用开关（`automation.go`）。全部存在服务数据目录的 `automations.json`，每个自动化保留最近 20 次运行：开始和结束时间、对话、第几轮、结果（运行中、通过、失败、已中断、已跳过）和一句话总结。

cron 是标准 5 段写法（分 时 日 月 周），按本地时间，支持 `*`、范围、列表、步长和英文缩写；日和星期同时指定时任一匹配即运行。常见写法会显示成中文，例如「工作日 9:00」「每周一、三 10:00」。

## 运行

调度器在后台服务里，每 15 秒检查一次（`automation_run.go`）。

- 到点后用 `submit` 在自动化的项目里新开对话，标题为「名称 · 日期」。项目不是当前打开的项目时，对话直接建在后台项目里，不切换窗口的项目。
- 上一次运行还没结束时，这次记为「已跳过」。
- 电脑睡眠或服务没运行而错过的时间，恢复后只补跑一次，记为补跑。
- 一轮结束的条件是对话不再忙碌、没有排队消息、也没有待处理的审批或提问。
- 检查命令在登录 shell 里执行，最长 10 分钟。没通过时把最后 4000 字输出发回同一个对话。
- 用户在对话里停止，或运行中关掉开关，记为「已中断」。
- 结束时推送一次「名称 · 结果（第 N/M 轮）」，自动化对话自己的「对话完成」推送不再发。运行中需要审批时，手机照常收到「需要你的确认」，Claude Code 的审批和后台项目的审批也包括在内。
- 服务重启时，上次没结束的运行记为「已中断」。

## 后台服务

有启用的自动化时，后台服务不会因为没有窗口而空闲退出。同时在 `~/Library/LaunchAgents/com.daodao.miya.service.plist` 安装一个登录时启动服务的任务；没有启用的自动化时卸载。这个任务只负责启动服务，服务自己的单实例锁保证只有一个在运行；没有设 `KeepAlive`，应用更新时替换服务不会和它冲突。

## 界面

Automations 页面（`view_automations.go`）有三个画面：

- 列表：按 agent 着色的图标、名称、项目和完成标准、时间和下次运行、上次结果、开关、立即运行、打开上次对话。
- 新建和编辑：一句话输入框，项目和 agent 在输入框底栏；整理中显示骨架，失败可以重试。
- 详情：下次运行、最近通过次数、平均轮数、指令和设置、运行历史，每条历史可以打开对应对话。删除要点两次。

侧边栏里自动化发起的对话显示为时钟图标。界面不直接使用具体 agent 的名字，只通过 `agentBackend`。

手机端从侧栏的「自动化」进入，查看全部项目的执行计划、启用状态、运行历史和结构化结果，并打开对应的运行对话。页面打开时按需读取，每 5 秒刷新；断线时保留本次已读取的内容。手机端和桌面后台均需更新到支持此接口的版本。

## 已知限制

- 只在后台服务模式下运行，设置了 `MIYA_SERVICE=0` 时没有自动化。
- 在项目目录里直接运行，和手动发消息一样，可能和你正在做的修改冲突。
- 手机端自动化页面支持查看；创建和编辑可在桌面端进行，也可以在手机对话里描述操作。
- 整理一句话每次要等 15 秒左右，消耗少量额度。

## 以后可以加

| 功能 | 什么时候值得加 |
| --- | --- |
| 独立 worktree 运行 | 自动化会改代码，并且和手动工作冲突时 |
| 收件箱与「无事可报自动归档」 | 自动化多了，空结果的推送开始打扰人时 |
| 每次都继续同一个对话 | 需要跨天保持上下文的长期跟进 |
| 每个自动化单独设模型与推理强度 | 默认模型不合适时 |
| 事件触发（GitHub、webhook） | 定时轮询太慢或太浪费时 |
| 手机端管理页 | 经常需要在手机上开关自动化时 |

## 运行结果

每次运行结束都会留下一份结构化结果，存在这次运行的记录里，和对话是否还在无关（`automation_report.go`）。

- 运行时发出的消息是指令，加上一段说明：结束前调用 miya 的 `report_result` 工具上报 `summary`（总结）、`findings`（要点）、`metrics`（指标，含名称、数值、单位）、`artifacts`（产出文件或链接）、`needs_user`（是否需要人处理）。多次调用以最后一次为准；不是自动化运行的对话调用会报错。Claude Code 调用它不需要确认。
- agent 没有上报时，Miya 用对话最后一条回复和改过的文件生成自动摘要，并标明是自动摘要。
- 运行通过且有上报结果时，运行总结和推送内容使用上报的 `summary`。
- 「带上上次结果」开关默认打开：下次运行时附上最近一次有结果的运行的结构化结果，要求 agent 对比，指出新增、消失和变化较大的项。之前的对话删除了也不影响。
- 详情页每条运行下显示结构化结果，最近一次默认展开。

只保留最近 20 次运行。需要完整明细或长期趋势时，在指令里要求 agent 把每次结果写入项目里的文件。
