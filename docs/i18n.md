# 界面语言

桌面端和手机端都在设置中提供「跟随系统 / 简体中文 / English」，首次运行默认跟随系统。Miya 根据应用声明的语言匹配系统偏好；没有匹配时回退英文。选择语言后立即刷新界面，并在下次启动时恢复。

语言属于当前设备，不跟随工作空间，也不从服务器同步。旧服务协议中的 `locale` 字段不再决定界面语言。项目名、工作空间名、用户消息和 Agent 回复保留原文。

## 修改文案

应用文案保存在 `locales/en.json` 和 `locales/zh-Hans.json`，以英文为源语言。Miya 自己的 `locales/gen` 校验两份目录并生成 `locales/catalog_gen.go`，运行时由 `internal/i18ncatalog` 加载嵌入的 JSON，不依赖界面框架。

新增文案时，在两个 JSON 中添加相同的消息 ID，然后在界面中调用 `tr("English source text")`，或使用生成的类型化函数。`tr` 通过同一份 Miya catalog 翻译源文案；带格式参数的现有文案使用 `fmt.Sprintf(tr("… %s …"), value)`。翻译必须保留参数类型、格式和顺序，生成器及测试会校验两份目录。当前目录没有 ICU 参数、plural 或 select；运行时保留 ICU 单引号转义（两个单引号表示一个单引号），未转义的花括号会报错。需要字面花括号时用单引号引用；增加 ICU 参数前须同时扩展解析器和生成器。

`main` 以外的包同样调用 `tr("…")`：在包内声明私有的 `func tr(s string) string { return locales.T(s) }`，不要直接写 `locales.T("…")`。`TestProductSourceCopyUsesEnglishCatalog` 只识别名为 `tr` 的调用，用它检查每条源文案都在目录中。当前界面语言由 `locales.SetCurrent` 记录。

不要把用户内容传给翻译函数，也不要翻译页面 ID、协议字段、模型 ID 或路径。命令面板保留英文命令元数据，并单独翻译显示内容，以同时支持中英文搜索。

```sh
go generate ./locales
go run ./locales/gen -check
go test ./...
```

提交语言目录和生成的 Go 文件，使普通 `go build`、`go test` 也能直接运行。`-check` 不写文件，同时检查键、printf 参数、消息语法和生成文件是否过期。`locales.Match` 使用 BCP 47 和 CLDR 匹配，找不到相同语言和文字系统时回退英文。界面与生成访问器统一使用 `locales.Current`；设置为空语言时恢复跟随系统。日期和数值格式继续由各自的显示逻辑及界面框架处理。

旧界面的 catalog 注册和语言适配已删除。Miya 自有生成器管理语言目录，NSGo 打包不覆盖生成文件；macOS/iOS 的 `miya.macos.info` / `miya.ios.info` 显式声明 `en` 和 `zh-Hans`，新增语言时需同步这些声明和原生资源。

原生 iOS 文件浏览页及权限说明的翻译位于 `resources/languages/*.lproj`。文件目录页面根据客户端的 `Accept-Language` 渲染应用标签，保留项目和文件名称。`nsgo.yaml` 的资源列表经打包 overlay 纳入这些原生语言目录。
