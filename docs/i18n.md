# 界面语言

桌面端和手机端都在设置中提供「跟随系统 / 简体中文 / English」，首次运行默认跟随系统。MyGo 根据应用声明的语言匹配系统偏好；没有匹配时回退英文。选择语言后立即刷新界面，并在下次启动时恢复。

语言属于当前设备，不跟随工作空间，也不从服务器同步。旧服务协议中的 `locale` 字段不再决定界面语言。项目名、工作空间名、用户消息和 Agent 回复保留原文。

## 修改文案

`mygo.json` 声明 `locales` 为语言目录，以英文为源语言。应用文案保存在 `locales/en.json` 和 `locales/zh-Hans.json`，由 MyGo 校验并生成 `locales/catalog_gen.go`。

新增文案时，在两个 JSON 中添加相同的消息 ID，然后在界面中调用 `tr("English source text")`，或使用生成的类型化函数。`tr` 通过同一份 MyGo catalog 翻译源文案；带格式参数的现有文案使用 `fmt.Sprintf(tr("… %s …"), value)`。翻译必须保留参数类型和顺序，测试会校验两份目录。

不要把用户内容传给翻译函数，也不要翻译页面 ID、协议字段、模型 ID 或路径。命令面板保留英文命令元数据，并单独翻译显示内容，以同时支持中英文搜索。

```sh
go tool mygo i18n check
go tool mygo generate
go test ./...
```

提交语言目录和生成的 Go 文件，使普通 `go build`、`go test` 也能直接运行。应用界面从 `ui.Context.Locale()` 读取 MyGo 已匹配的语言；`App.SetLocale("")` 恢复跟随系统。日期和数值格式继续由各自的显示逻辑及 MyGo 控件处理。

原生 iOS 文件浏览页及权限说明的翻译位于 `resources/languages/*.lproj`。文件目录页面根据客户端的 `Accept-Language` 渲染应用标签，保留项目和文件名称。iOS 构建脚本通过目录符号链接，让临时配置使用项目原始语言目录。
