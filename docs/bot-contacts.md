# Bot 联系人

联系人让名字、头像和人设保持稳定，执行引擎负责实际运行。多个联系人可以使用同一个 Codex、Claude Code 或 Pi 账号。

## 使用

从侧栏「联系人」进入列表，可从伙伴、研究员、工程师模板开始，也可以新建空白联系人。保存名称、头像、简介、人设、默认引擎、模型和推理档位后，点击联系人即可聊天。桌面侧栏同时提供直接进入联系人的入口。

每个联系人可以有多段日常聊天和不同项目的会话。聊天页显示联系人名字及「日常聊天」或项目名称。通过上下文菜单可以切回日常聊天、新开日常会话或进入已登记项目；资料页列出该联系人的全部未归档会话。再次点击联系人会继续最近使用的会话。

项目中的联系人聊天同时出现在原项目列表中，两处引用同一个会话、审批和运行状态。日常聊天使用联系人自己的工作目录，不会把内部目录列成代码项目。工作目录不是沙箱，访问权限与审批仍遵循原有 Agent 设置。

可以按名称和简介搜索、置顶联系人或将其归档。归档不会中断正在进行的工作，也不会删除会话；在「已归档联系人」中可恢复。运行中的会话仍能从全局活动区进入。删除一段会话沿用现有会话操作，不删除联系人。

手机的「联系人」入口使用当前连接电脑上的同一份资料和会话。可在手机创建、编辑、置顶、归档、选择项目及聊天。另一台电脑拥有自己的联系人，不按同名自动合并。断线保留当前表单；超时后重试同一个保存请求不会重复创建联系人。

## 配置生效

- 名称、头像和简介修改后立即更新显示。
- 人设及默认引擎、模型和推理档位用于新会话。旧会话保留创建时的配置，并提示「使用旧版人设」。
- 会话内主动选择的模型和推理档位只影响该会话，不修改其他联系人或全局默认值。
- 人设通过独立标记的输入上下文交给引擎，不改写用户原文、项目指令文件或用户全局 CLI 配置。原生历史重新加载时会移除这段界面隐藏的上下文。
- 人设不授予权限，也不代表用户同意执行外部操作。

项目聊天复用原项目的记忆作用域。日常聊天的自动召回只读取已启用的用户级偏好，不读取此前聊过的项目记忆，也不把内部工作目录当作项目事实的作用域。首版沿用共享用户记忆，未增加每个 Bot 独立的长期记忆系统。

## 数据与恢复

后台数据目录的 `contacts/contacts.json` 保存资料、版本、会话关联和请求回执；`contacts/avatars/` 按内容哈希保存头像；`contacts/workspaces/<BotID>/` 是日常聊天的工作目录。

新会话先保存稳定的本地身份与人设快照，再启动原生会话。原生 ID 与是否已经确认创建分别记录，避免把尚未成功发送的 Claude 草稿误认为可恢复的历史。重启后通过持久化关联恢复联系人，不依赖原窗口的数字会话编号。

保存与回执通过同一次原子文件替换提交；修改资料校验版本，阻止两端静默覆盖。损坏或不支持的资料文件会保留并报错，不自动当成空列表覆盖。客户端列表只接收历史人设的身份和版本，不在每次状态推送中重复传输人设正文。

核心实现位于 `internal/contacts/`；Controller 负责会话与服务组装；`internal/widgets/view_contacts.go` 是双端共用界面。服务和手机协议通过可选字段公布联系人能力，旧后台显示更新提示，现有项目聊天继续可用。

后台工作目录属于服务，窗口选择属于各自窗口。手机进入日常聊天或另一个窗口切换项目，不会替换当前窗口的聊天上下文。重连时，联系人的本地草稿和消息缓存按持久化联系人会话身份重新关联，避免误用后台重启后复用的数字编号。

## 验证范围

隔离测试覆盖持久化、重复请求、版本冲突、日常与项目隔离、三 Bot 共用引擎、原生输入与历史展示、人设冻结、用户记忆边界、手机请求与订阅、服务镜像、重启恢复、旧后台和跨电脑隔离。界面以 MyGo 原生 fixture 截图核验。真实模型计费调用与真机安装不属于本次自动回归。

2026-11-08 完整 `go test -race -p 2 -json ./...` 回归通过：1458 个测试项（含子测试）、33 个跳过、零失败。定向交互及记忆回归另重复三轮通过。
