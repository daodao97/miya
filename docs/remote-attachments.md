# 手机图片使用独立的二进制附件通道

手机上传原图、桌面返回缩略图时，新端通过现有 Tailcat 私有文件通道传输原始字节。聊天、审批、停止、会话增量等控制消息继续使用原来的 JSON 通道；图片正文不再占用这个通道的写锁。Tailcat 仍负责端到端加密，不增加公开监听端口，也不改变配对方式。

## 协商与旧端兼容

控制协议仍为 v5。桌面在 `hello.attachmentToken` 中附带当前控制连接专属的随机令牌，新手机接收后在请求中带 `binaryAttachments: true`。只有看见这个标志，桌面才使用新的缩略图回复。

- 新手机连接旧桌面：hello 没有令牌，继续发送原有 base64 图片。
- 旧手机连接新桌面：不发送启用标志，桌面继续返回原有 base64 缩略图。
- 新端之间：使用二进制正文和单次附件引用。传输失败时报告错误，不自动重新发送完整消息，避免重复执行。

这些是可选字段，未改变旧消息的含义。更早的控制协议版本仍遵守已有版本检查，不因附件能力放宽兼容范围。

## 上传和预览

手机使用同一个 Tailcat 身份连接 `FilesPort`，通过 HTTP PUT 逐张上传原始图片；控制请求只携带图片名称和附件 ID。服务在把请求交给现有发送逻辑之前，将这一连接的附件 ID 原子转换回图片数据，并移除临时记录。文字、目标会话、模型设置、排队和立即引导语义不变。

桌面先按现有规则验证图片属于请求的会话，再生成最长边 640 像素的缩略图。两个工作线程负责授权后的读取、生成和回复，最多排队 8 个预览请求，控制循环不等待图片处理。新端的 `image` 回复只带来源和 `attachment` ID；手机异步 HTTP GET 图片，不在读取控制消息的循环里等待。临时下载失败或队列繁忙时，手机最多按 1、2、4 秒退避重试三次，并重新请求单次附件 ID；旧连接的重试不会修改新连接的缓存。

项目文件浏览与下载仍走原有 HTTP 路径，支持 Range。附件请求使用独立保留路径 `/.miya-attachments/v1/<id>`，不会改变项目文件的访问范围。

## 生命周期与限制

- 每条控制连接生成 256 位随机令牌，每个附件 ID 为 128 位随机值；HTTP 请求通过 Authorization 头携带令牌。
- 附件只能由所属连接访问，不能跨连接引用。上传引用在整批校验后一次消费；缩略图在一次 GET 结束后释放，不能当作上传附件使用。
- 上传保持原限制：最多 6 张，单张 10 MiB，合计 20 MiB。正在接收的正文也占用数量和字节预算，接收失败会释放。
- 缩略图单张最多 2 MiB，独立预算最多 8 个、合计 16 MiB，上传不会消耗这个预算。
- 待使用附件两分钟失效，每 30 秒清理一次过期记录；断开控制连接即撤销令牌、清空记录并取消关联传输。
- 整批上传最多两分钟，手机附件 HTTP 连接最多两个；缩略图下载也有并发数量限制。新控制连接不会复用旧连接的附件。
- 图片处理失败、附件过期、超限或断线不绕过原有会话访问校验。上传失败保留手机草稿和选中的图片，用户可以重试。

## 验证与性能边界

`internal/remote/attachments_test.go` 覆盖二进制上传/下载、旧端回退、跨连接隔离、重复消费、截断正文、容量与过期、慢上传/下载期间控制消息继续通过，以及关闭连接取消上传。原有缩略图授权、缓存和发送测试继续运行。

```sh
go test ./...
go test -race ./internal/remote
go test -run '^$' -bench '^BenchmarkAttachmentUpload$' -benchmem -benchtime=300ms ./internal/remote
```

2026-11-02 在本机 Apple M3、darwin/arm64 上的单次基准结果：

| 上传正文 | 旧 JSON/base64 | 新附件 HTTP＋控制消息 | 旧/新累计分配 |
| --- | --- | --- | --- |
| 32 KiB | 92.99 µs | 87.15 µs | 139,383 / 81,649 B |
| 1 MiB | 3.400 ms | 0.513 ms | 11,279,744 / 1,115,950 B |

基准使用正式的附件处理和控制编解码，通过本机 HTTP 与内存控制连接运行；不包含 Tailcat 加密、中继、真实网络及图片解码。大图收益明显，小图的 HTTP 开销会抵消一部分编码收益。去掉上传 base64 后，正文封装约减少 25%，实际链路还包含 HTTP 和加密开销；已有压缩的下行不能据此承诺同等带宽收益。

本次没有在 iPhone 真机测量，也没有安装或发布新应用。真机仍需检查弱网大图上传、并发审批/停止、切换桌面和断线重连时的耗时、峰值内存与缓存结果。
