# 会话中的远程桌面

手机会话中的接管授权卡直接显示目标授权框的标题、说明、单窗口预览及原生按钮（例如「允许访问 / 不允许」）。按钮可用状态来自 Mac；未填密码导致允许按钮禁用时，手机卡片显示蓝色「填写授权信息」入口，进入同一窗口填写后再显示可用的「允许访问」。点击预览也可进入该窗口的全屏操作界面；密码在隐藏输入框中填写，发送后清空，不进入聊天记录。授权卡无需额外的「选择窗口」或「已完成，继续」步骤。

原生默认按钮可用时显示蓝色（依据 AX 默认／取消属性，按钮文字仅用于展示），提交中或连接不可用时显示灰色。「填写授权信息」只打开目标窗口，不执行原生允许动作；Mac 上实际禁用的按钮仍不可提交。普通 MCP 确认不打开窗口预览，无需填写字段的请求直接在会话卡片中完成。

进入单窗口操作后，输入栏下方直接显示该窗口当前的原生按钮；键盘打开时仍可操作。发送文字后，按钮状态自动刷新，可直接在本页允许或拒绝，不必先回到会话卡片。按钮提交时再次核对窗口 ID/PID 和原生可用状态，等待结果期间阻止重复提交。密码错误或中间步骤仍停留在操作页。后台处理完同一授权请求后，手机自动关闭操作页并返回原会话；仅窗口消失或另一张授权卡完成不会触发返回。

Agent 调用 `request_desktop_control({"reason":"填写授权密码","window_app":"系统设置","window_title":"授权"})` 发起接管。`window_app` 可填应用名称或 bundle ID，`window_title` 可填窗口标题片段；两者可选。发起时记录匹配窗口的 ID 和所属 PID，后续预览及输入持续绑定该身份。未提供窗口信息时使用当时最前面的可共享应用窗口，并在预览中显示实际窗口内容；明确选择器匹配不唯一时不猜测目标，提供错误状态下的窗口入口。目标关闭后不回退到其他窗口或完整桌面。

目标窗口接管卡正常连接时每两秒更新一次预览和原生按钮状态；刷新失败后保留上次画面、窗口身份和按钮，暂停自动刷新，用户点「重试预览」后恢复。暂停期间不允许使用旧画面的授权按钮，相同图片数据复用已有图像对象，避免纹理反复替换。普通工具调用权限确认不自动采集前台窗口。只读取辅助功能中的静态文字、按钮标题和可用状态，不读取任何可编辑字段或密码值。点击卡片原生按钮，或在单窗口界面点击/按回车操作对应按钮，均作用于同一个 Mac 窗口。原生按钮操作成功发送后，依据窗口身份和生命周期确认接管结果，不按「允许／好／确定」等固定文案推断。目标窗口持续消失且没有同一进程或应用的新窗口出现时才完成请求；取消结果来自原生 AX 取消属性。密码错误而弹窗仍在、或出现同一应用的后续窗口时继续等待。窗口状态读取失败不会被当作关闭，并在观察期内重试。普通问题和外部审批仍需按其原有表单语义回答。

完整桌面保留在「更多 → 远程桌面」，单屏时直接连接，多屏时先列出「桌面 1 · 屏幕名称」「桌面 2 · 屏幕名称」，同时显示分辨率和主屏幕标记；不再显示确认页。显示器熄灭时先唤醒，采集失败时唤醒后重试一次。两种操作界面都是 MyGo 原生页面（路由 `/desktop`），不使用 WebView 或网页；页面关闭边缘返回手势，避免与远程手势冲突，点左上角返回键回到会话，离开页面即结束控制。单窗口界面的「切换窗口」用于多步授权或需要重新定位目标的情况。支持点击、滑动、鼠标拖动、缩放、文字输入及常用键盘操作。默认为触控板模式：画面上显示本地光标，单指移动光标（Mac 同步移动鼠标，可触发悬停），轻点在光标处点击，连续两次轻点为双击，按住约半秒后移动为拖动，双指滑动滚动、捏合缩放、双指轻点右键。顶栏按钮一键切换到触控模式，可在「更多」中选择点击·滚动、拖动或移动放大后的画面。所选模式保存在手机本地的 `desktop-control.json`，不发往 Mac，下次打开沿用。输入按顺序排队：连续移动只保留最新位置，连续滚动累加，同一时刻仅一个请求，队列最多 64 项；点击等动作排在之前的移动之后发送。

## 支持范围

「完整桌面」的「桌面」列表按主屏幕优先、其余屏幕的位置顺序编号，读取 macOS 的显示器名称，不把显示器 ID 当名称。单屏直接进入，多屏先选择；操作页顶栏显示当前「桌面 N · 屏幕名称」，点「切换桌面」可重新选择，同页仍可切到窗口或应用列表。这里的桌面对应显示器，不是 macOS Spaces。

显示器选择通过 `GET /displays` 和 `POST /display`，仅普通菜单租约可用。每个目标以 CoreGraphics ID 和稳定 UUID 双重绑定；采集和输入都在原生层重新核验，屏幕断开或身份不符时暂停画面、清空输入并返回列表，不自动跳回主屏幕。切屏后必须开始所选目标并获得新画面才能输入；手机按目标版本丢弃在途旧画面和旧输入结果，输入请求携带所选 ID/UUID，避免迟到动作作用于另一屏。切屏保持当前防窥状态，离开控制后按原逻辑恢复。旧手机仍可默认控制主屏幕，旧后台不显示多屏入口。

普通远程桌面的「更多选项 → 防窥模式」可让 Mac 的所有在线显示器变黑，手机继续显示和操作桌面；默认关闭，不保存为下次自动开启。切换窗口或打开应用期间保持防窥，关闭控制页、断线或控制租约到期后恢复。Mac 本机按 **Control–Option–Command–P** 可立即恢复，手机会重新读取实际开关状态；状态读取失败时仍可点「恢复 Mac 屏幕」。审批接管租约不提供此能力，旧后台不显示入口。

防窥通过公开 CoreGraphics gamma 表 API 实现，思路参考 [Umbra](https://github.com/frapsd/Umbra)，代码独立实现。开启时先保存各显示器原表，再将 RGB 表设为零并读回核验；任一显示器失败则恢复并返回错误。ScreenCaptureKit 读取的桌面内容不受这些扫描输出阶段的颜色表影响。独立的 `-desktop-privacy` 辅助进程负责修改和恢复，父服务通过管道和心跳维持它；管道断开、三秒未收到心跳、本机快捷键或终止信号会恢复后退出。辅助进程异常退出时由 WindowServer 释放其 gamma 修改；测试仅终止这个专用进程，不终止后台服务。

此模式遮蔽本地显示内容，Mac 仍处于登录会话，不阻止本机键鼠或代替系统锁屏。它不关闭显示器电源、不修改背光亮度、不创建虚拟显示器，也不取得独占显示控制。显示器接入或颜色表变化时重新核验和应用；无法维持时退出防窥，手机状态随轮询更新。多显示器切换、HDR 与第三方调色软件的组合仍需按实际设备验证，未通过核验时不会报告开启成功。

普通远程桌面的悬浮工具栏提供「打开应用」，窗口选择页也可切到「应用」。应用列表参考 [Reminal 的应用启动器](https://github.com/harshalgajjar/Reminal/blob/main/internal/client/windows_backends.go)，独立实现常用目录扫描：`/Applications`、`/System/Applications`、`~/Applications` 及其中一层子目录，另列出 Finder。以原生图标组成三列网格，可按应用名称、bundle ID 或路径搜索；不扫描应用包内部的辅助程序，同名应用保留各自的路径身份。

点击后在 Mac 启动应用，已经运行的应用切到前台。手机最多等待九秒，按 bundle ID 和窗口 ID/PID 识别目标，优先进入唯一新窗口，其次进入该应用唯一已有窗口；没有窗口或存在多个候选时保留窗口选择，也可查看完整桌面。启动失败可在列表重试；Mac 锁屏时先进入完整桌面解锁，之后重新打开应用。审批接管页不提供应用列表或启动接口。旧 Mac 后台未提供应用能力时隐藏入口。

应用列表与启动使用现有控制令牌，路径为 `GET /apps`、`POST /launch`，仅普通菜单控制租约可调用。启动时重新核对已安装列表、系统权限、锁屏与租约状态，仅将已列出的应用路径作为参数交给 `/usr/bin/open -a`，不执行手机提交的命令、URL 或任意文件。关闭页面或断线取消在途启动请求；启动不会隐式开始采集，切入窗口仍须等待新画面才能输入。图标以 48×48 PNG 传输，总图标预算 600 KiB，列表与图标仅驻留手机内存。

macOS 打包使用 `scripts/build-macos.sh`，它启用 cgo 原生桥接；直接运行 MyGo 的默认无 cgo 构建不会包含远程桌面。

单窗口及各显示器采集均需要 macOS 14 及以上，手机和桌面后台均需更新。Mac 必须已登录。显示器熄灭时，开始控制及采集前会声明一次本机用户活动（效果同 `caffeinate -u`）点亮显示器；锁屏时随即显示锁屏界面，可在画面中输入登录密码解锁。控制期间至多每 5 秒刷新一次，结束后恢复系统原有的空闲熄屏；不修改电源或共享设置，不持有常亮断言。单窗口画面使用 ScreenCaptureKit 的独立窗口过滤器，输入坐标按目标窗口当前边界映射；输入前验证窗口身份及焦点，键盘事件发送给目标进程。完整桌面模式的鼠标坐标映射到所选显示器当前的全局边界（包括负坐标）；键盘输入仍进入系统当前焦点窗口。缩放仅用于手机本地查看。Touch ID、安全桌面或系统禁止远程操作的授权仍须在 Mac 上完成。

不包含单窗口视频流、音频、剪贴板同步或 60 fps 视频。Box 等独立云电脑不会自动成为这条连接的目标；需要先在 Mac 的可见应用中打开其桌面，才能通过主屏幕操作它。设计参考 [Reminal](https://github.com/harshalgajjar/Reminal) 的画面与输入分流、手机触控及人工接管方式，代码独立实现。

首次使用须在 Mac 的「系统设置 → 隐私与安全性」中允许 Miya 的「录屏与系统录音」（旧系统称「屏幕录制」）和「辅助功能」。系统要求重启时只正常重开需要授权的应用；后台有任务时遵循[安装与后台服务升级](install-and-upgrade.md)，不得强杀后台。临时开发构建的代码签名变化可能使原授权失效，开关仍打开时也可能需要在设置中移除旧条目，再添加新应用。不能只凭设置中的开关声称权限已生效，须实际采集并检查输入。

## 保存密码与解锁 Mac

从手机菜单打开完整桌面或自选窗口后，Mac 锁屏时显示专用密码框。输入登录密码并点「解锁」即可；默认不保存。勾选「保存密码，下次验证身份后自动解锁」时，先通过 Face ID／设备密码验证，只有 Mac 确认解锁成功后才写入手机的系统钥匙串。密码按已配对的 Mac 分开保存，仅本设备可用，不写入普通偏好文件、聊天记录或日志。

后续打开远程桌面或观察到一次新的锁屏时，已保存密码会触发一次身份验证，通过后自动提交。取消验证或请求失败不会反复弹出验证或自动重试，可点「验证解锁」再次使用，或手动输入。服务返回密码未能解锁（401）时会尝试删除该已保存密码，要求重新输入；网络或锁屏状态读取失败不会当作密码错误。点「忘记密码」删除当前 Mac 的凭据；移除桌面连接也会清理对应钥匙串项。钥匙串失败会显示提示，仍可取消保存后手动解锁。

Agent 发起的授权窗口接管不提供解锁、保存或使用登录密码。仅已开始且仍有效的控制会话能调用 `POST /unlock`。Mac 在唤醒前、唤醒后以及各次输入前检查锁屏状态；已解锁时返回 409，不再输入。解锁期间禁止交错的普通输入及窗口切换，断线或关闭立即取消后续步骤。每次请求只提交一次，最多等待五秒确认结果。

锁屏时 `/frame` 返回 423 和 `X-Miya-Screen-Locked: 1`，不依赖锁屏截图成功，也不会因自选窗口在锁屏时不可见而结束会话。手机移除旧画面和排队输入、收起普通键盘控件，解锁后恢复画面轮询。兼容仍返回锁屏图片及同一标记的桌面版本。

此功能用于已经登录的 macOS 会话锁屏，不支持开机 FileVault 解锁，也不能代替要求在 Mac 本机完成的 Touch ID 或系统确认。手机需处于前台；每次使用保存的密码仍需设备身份验证。

## 传输和控制会话

- 复用原有 Tailcat 配对和端到端加密。控制连接继续传递聊天、审批以及新增的 `desktop-open` / `desktop-close`，画面与输入通过私有 FilesPort 的独立 HTTP 请求传输；Mac 不开放公网端口。
- v5 协议增加可选 `state.desktopControl` 和 `state.desktopWindows` 能力标志，旧端忽略。新手机连接旧桌面显示更新说明，不改变原协议消息含义。
- `desktop-open` 必须带有效的稳定会话 ID，返回与当前连接绑定的随机 256 位令牌；每次仅允许一个操作界面，十分钟绝对到期，关闭或断线即撤销。正在使用远程桌面时，后台服务视为忙碌，等待结束后才执行空闲升级。
- `desktop-preview` 仅在精确匹配的待处理审批及会话内允许；预览缩略图只驻留手机内存，不写附件缓存、聊天记录或磁盘。断线、审批处理及内容版本改变时移除。`desktop-action` 重新读取原生按钮状态，拒绝已禁用、重复名称、过期审批或其他会话的操作。预览不创建独占控制租约、不请求新的系统权限；缺权限时给出本机授权提示。
- Mac 私有 HTTP 路径为 `/.miya-desktop/v1/{session,windows,select,displays,display,apps,launch,privacy,start,frame,input,unlock,actions,action,stop}`，请求经 Authorization 携带令牌。`privacy` 的 GET 读取状态、POST 切换，仅菜单租约允许；开启还要求已开始控制且十秒内取得成功画面。`actions` 只返回当前授权窗口的按钮元数据，`action` 再读取原生按钮状态并核验请求中的窗口 ID/PID；主屏幕会话不提供这两项操作。手机原生页面经已配对 Tailcat 通道的独立文件流直接请求这些路径，令牌只保存在手机进程内存中，作为本次控制租约的凭证；手机不再开放本机回环端口，不经过 WebView、Cookie 或网页。
- 控制租约的 `/start` 之前拒绝实时采集及输入；授权卡另有受待处理审批约束的只读单窗口缩略图通道。切换窗口撤销输入状态，须收到该窗口的新画面才能输入。原生采集使用 ScreenCaptureKit，最长边 1600 像素、JPEG 质量 0.65、单帧最多 2 MiB，最多四次采集/秒。前端串行轮询，正常间隔 300 ms；实际帧率取决于采集和网络耗时。慢帧不会阻塞输入、聊天或审批。
- 输入校验归一化坐标、操作枚举、修饰键和正文大小；文字每次最多 4096 UTF-8 字节，Unicode 事件分块且不拆开代理对，不借用系统剪贴板。输入之前须有十秒以内的成功画面。服务串行发送输入，拒绝过快的操作。
- 截图仅驻留内存，使用 `no-store`，不进入聊天记录或图片缓存。App 进入后台时断开连接并结束控制，结束或关闭时清空输入及画面。旧连接、过期会话和撤销后的在途画面不能继续操作或交付。
